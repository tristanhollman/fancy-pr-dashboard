Review counts, without guesswork.

The same meaning in every layout. Color helps; text always carries the answer.

1/2 required

Required reviewer entries

One of two required people or groups has approved. A required group counts once, using its own vote, not a sum of its members.

You: pending

Your next action is separate

Keep your vote distinct from the team's progress. Waiting for the author and changes requested are not approvals.

None / Unknown

No invented certainty

No required entries is not missing data. Neither means mergeable: branch policies and other checks are a separate concern.

2/3 individuals

Participation belongs in detail

Individual approvals exclude group containers. The current app's team/reviewer ratio must not simply be relabeled "required."

Recommendation: ship the Workbench foundation.

It gives frequent users a fast scan path without sacrificing the PR description. Borrow Radar's clear panel borders and Focus Inbox's readable inspector. Treat these as alternative directions, not three modes V1 must implement.

Scope boundary: these are browser-based layout studies, not changes to the live TUI. Repo grouping, selection, vote status, age, and changed-file counts use concepts the app already supports. Descriptions, branches in the inspector, and explicitly required reviewer entries need to be retained in the app's data model. Policy evaluation is not implemented or inferred here. Refresh is simulated; production auto-refresh remains a separate task.

Implementation guardrails: use Ink borders, fixed-cell columns, and flat ANSI colors; no gradients, images, web fonts, or mouse-only actions are needed. The browser studies use type-size differences for emphasis; a real terminal uses one font size, with bold, color, and spacing instead. Keep Enter opening the selected PR, add p for details, retain the existing filter keys, and propose Tab for pane focus with 1-4 for queue scopes. This HTML keeps native browser Tab navigation. At about 120 columns, drop the repo rail and secondary metadata; at 80, show the queue or inspector, never both squeezed together. Below 80, retain the repo, title, required count, and action in stacked rows.

Before implementation: confirm required-group semantics against actual Azure DevOps payloads; handle absent descriptions and unknown review requirements; preserve selection across refreshes; paginate or virtualize long lists; keep per-pane scroll position; sanitize description control sequences; and provide an ASCII/high-contrast fallback. Browser dimensions are estimates, not a terminal resize test. No configuration or CLI flags are added.
